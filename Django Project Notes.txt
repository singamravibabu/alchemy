- This relationship is handled through ForeignKey in Django.

CREATE 'CRUD' WEB APPLICATION
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
CRUD is the acronym for Create, Read, Update, and Delete
- Four functions represent the minimum operations use in database applications.

Create (C)
- Creates new records in the systems
- Example: Create an article and the system will register it

Read (R)
- Read (retrieves) existing data records in the system
- Example: The system retrieves posted articles to display them

Update (U)
- Updates existing data records
- Example: Update the posted blog articles and the system updates the records

Delete (D)
- Deletes existing data records from the system
- Bloggers delete posted blog articles, and the system removes the records


CRUD in web applications
========================
In web applications, the CRUD concept is executed through web pages.
- Content editors go to the content posting page (Create Page) to post their content.
- The posted content can be read by users on a list-style page with a list of many content items (List Page) or a particular content page (Detail Page).
- When content editors want to edit or delete the existing content, they can edit or delete it on the Update Page or Delete Page.


Basic CRUD Structure in Django
==============================
- Django framework is well-designed to execute the 'CRUD concept' efficiently.
- Five key design points exist to build a CRUD-based web application in Django.

1. views.py
-----------
- views.py is used to build logic to handle HTTP requests dispatched from urls.py
- Django provides premade logic templates names 'generic views'
- By using generic views, you can build web applications with simple code
- To handle each CRUD page, you need to design different views for each page

2. urls.py
----------
- urls.py is used as a 'URL dispatcher'
- Dispatches the request to related views (defined in the views.py file)
- To handle each CRUD page, you need to define different URL patterns for each page

3. Templates
------------
- 'Django templates' usually consists of multiple HTML files
- They are saved under 'templates' directory whose path is defined in 'settings.py'
- Them template HTML files are used to convert data handled by views.py into the HTML format
- To handle each CRUD page, you usually need to prepare different HTML files for each page

4. settings.py
--------------
- Defining key paths or registering domains to allow access to the web application

5. models.py
------------
- models.py is used to design a database for web application


Django Generic Views
====================
- Build-in class-based views
- Eliminates repetitive coding
- Provides frequently used logic in class formats

Base views:
	View
	TemplateView
	RedirectView

Generic display views:
	ListView	Read
	DetailView	Read
Generic editing views:
	FormView
	CreateView	Create
	UpdateView	Update
	DeleteView	Delete


- Generic views in Django are built-in class-based views.
- Generic views are developed to eliminate repetitive coding by providing frequently used logic in class format.
- Using generic views, we can build web applications with simple code.
- Base view: View is ancestor of all views
- RedirectView is used for URL redirections


In a simple CRUD application, there are five frequently used generic views:
ListView		- R of (CRUD)
DetailView		- R of (CRUD)
CreateView		- C of (CRUD)
UpdateView		- U of (CRUD)
DeleteView		- D of (CRUD)


ListView
-----------
- Provides logic to display list of objects (from a database)

DetailView
-----------
- Provides logic to display a particular object (from a database)

CreateView
----------
- Provides the logic to display an input form to create an object
- When inputs are submitted, CreateView handles the inputs and registers the data in a database

UpdateView
----------
- Provides logic to display an input form to update an object
- When inputs are submitted, UpdateView handles the modification of the registered data in a database

DeleteView
- Provides logic to display a page for the data delete action and handle the data delete process


How to Write Class-Based Views with Generic Views
=================================================
views.py
--------
from django.views.generic import ListView
from .models import MyModel
class MyView(ListView):
	template_name = 'list.html'
	model = MyModel
	def get_context_data(self, **kwargs):
		context = super().get_context_data(**kwargs)
		context['now'] = timezone.now()
		return context


The above code has four sections:
1. Import generic views and models used in this view
2. Create a new view using a generic view
3. Set 'attribute values' for each attribute defined for each generic view
4. Customize the generic view (e.g., set a new context)


1. Import generic views and models used in this view
=====================================================
Import generic views
--------------------
First we need to import generic views
Generic views are stored in jango.view.generic
Example: ListView

from django.views.generic import ListView


Import models
-------------
Import the models to be used in the view

from .models import MyModel

The . (dot) means that the same directory as the views.py is located.


2. Create a new view using a generic view
=========================================
- We can create a view through inheritance
- The way to write a class-based view:
	-> Class is written in PascalCase: MyView
	-> Use the parent class name as an argument of the class to inherit the parent class, like ListView: MyView(ListView)


3. Set 'attribute values' for each attribute defined for each generic view
=========================================================
- Each generic view has its own attributes
- As generic views inherit attributes from their ancestor views, several common attributes are used for different generic views.
- There are two attributes in the example, there are many other attributes:
	template_name : set an html file used for this view
	model : set a model to be used for this view


4. Customize the generic view
=============================
- Generic views are equipped with basic functionalities, you may need to customize them.
- You can do:
	-> add a query to show selected data or to change the order of content items
	-> add context (a dictionary of data that is passed from a view to an HTML template)
	-> add logic to display content such as differentiating user interface depending on login status
- Customization of views is done in a way that overrides in the generic view.

	def get_context_data(self, **kwargs):
		context = super().get_context_data(**kwargs)
		context['now'] = timezone.now()
		return context


This get_context_data is initially defined in SingleObjectMixin class.


Generic view basic attributes
*****************************
model
========
- Defines the model for which the view will display data
- The model attribute can be replaced by the queryset attribute
- Its defined in SingleObjectMixin and MultipleObjectMixin
	'model = MyModel'


queryset
========
- Also used to define the model for the view
- querset give more functionalities using several method:
	-> all(): retrieves all objects
		'queryset = ModelName.objects.all()'
		same as 'model = ModelName' 
	-> filter(): returns objects that match given lookup parameters
	-> order_by(): returns objects in order, you can use "-"
		order_by('name')
		order_by('-name') : to reverse the order

template_name
=============
- Defines the path of the HTML file template for the view
- The path of the file should be relative to the templates directory set in the settings.py file
- The template_name attribute is defined in TemplateResponseMixin

context_object_name
===================
- Used to add a name to the object passed to template files

1. Use object_list for lists

	course_list

fields
=========
- Used to define model fields shown in the input form pages (create page and update page)
- This attribute is required if you are generating the form class automatically.
- The fields attribute is defined in ModelFormMixin

success_url
===========
- Used to define the URL to redirect to when the form is successfully processed.
- Required for generic editing views
- reverse_lazy() is resolve Django URL names into URL paths

Django Template Language (DTL)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
-> DTL is important for creating Django templates
-> Django template language serve as a bridge between HTML and Python code, especially for data passed from views (views.py)
-> Using DTL you can embed variables passed by views.py or add simple logic in an HTML template file.


{{variable}}
	-> displays data (objects) passed by views.py using this format


{{name|filter}}
	-> Using filters we can modify variables for display


{{name|lower}} -> displays the value of the {{name}} variable in lowercase text

65. Extend Templates - {% extends %} tag

-> In a website, there are several pages using a similar design structure.
-> Django templates can support the creation of a master template.
-> Each page can customize the master template by extending the master template.
-> The {% extends %} tag is used to extend the master template.

Steps:
1. Create a parent.html (or base.html)
2. In the parent file, add code for commonly used sections.
3. In the parent file, add {% block name %} and {% endblock %} for the section that you want to customize.
4. Create child.html
5. In the child file, add {% extends "parent.html" %} in the beginning of the file.
6. In the child file, add code between {% block name %} and {% endblock %}

101. Static Files in Development Environment - {% static %} tag

-> Static files are files that don't change dynamically, such as image, video, CSS, and JavaScript files.

102. Static directory location

-> The static directory should be registered in the settings.py file so that Django can handle static files properly.

STATIC_URL = 'static/'

104. {% static %} tag

-> In Django template files, {% static %} tags are used to access the static files stored under the static directory.
-> There are two rules:
1. Add {% load static %} tag at the beginning of each template file. With this tag, the template file loads static files. In extended template files, we also need to put this tag even though the parent file has this tag.
2. Use {% static 'file path' %} tag where we need to define the static file path. The file path should be written as 'relative path from the static directory'.

107. STATIC_URL and STATICFILES_DIRS

-> STATIC_URL defines the URL that is linked with the project directory locations defined by STATICFILES_DIRS.
-> The 'static' directory usually set directly under the project directory, but we can also set it under each app.
-> WE can setup multiple 'static' directories.
-> Django handles the 'static' files in the different 'static' directories as if they are under the same directory.
-> For example, when there is a HTTP request 'http://127.0.0.1:8000/static/img-1.jpg', Django gets resource from the 'static' directory under the 'project1' directory.

-> When there is a HTTP request 'http://127.0.0.1:8000/static/img-2.jpg', Django gets the resource from the 'static' directory under the 'app_a' (employee_learning).
